# Audit 001, click-through both themes (2026-10-10)

- Mode: antislop AFTER (audit only, no fixes until findings are approved individually).
- Scope: full front end, light + dark, desktop + 390px, every view and interactive element.
- Trigger: DESIGN.md demands "Both modes fully functional, both verified by contrast check and by click-through before delivery" (docs/DESIGN.md:96). This audit runs that click-through.
- Method: live app at http://localhost:5199 against the real FastAPI backend on :8010, driven with the Chrome DevTools MCP. Contrast is computed in-page on the composited ancestor background (RGBA stack walk), not from token pairs alone. Screenshots are not used (the reviewer cannot read images), so every claim is backed by a DOM or computed-style reading.
- Environment note: Docker was unavailable. Postgres ran from a throwaway cluster (port 55432) with `backend/db/schema.sql` loaded (14 harmless errors from TimescaleDB statements: `timescaledb`, `create_hypertable`, `time_bucket`, `add_continuous_aggregate_policy`, `add_retention_policy`). Redis absent. Backend logged a stale-model warning (`lgbm_signals_20260816_080420`, age 55d > 45d) and inert drift monitoring; the numbers on screen are therefore real API responses but from a stale artifact.

## Findings (numbered, priority order)

Priorities: P1 blocks the "both modes verified" claim, P2 is a real defect a user hits, P3 is polish.

`--warning` (`#a85c05`, theme.css:58) is used as foreground text at 8.5 to 11px on light tints that the token-pair test never samples. Measured ratios, all normal text, need 4.5:

| Element | Ratio | Size/weight | Background |
|---|---|---|---|
| DataFreshnessBadge "TERTUNDA 10 MNT" (Dashboard, Markets, every view) | 3.88 | 10px / 700 | rgb(230,226,221) |
| DataFreshnessBadge "data 1 hr lalu" (`--muted-foreground`) | 4.16 | 10px / 400 | rgb(230,226,221) |
| Advisor "Kepatuhan OJK:" | 4.09 | 11px / 600 | rgb(237,232,226) |
| SignalCard "Probabilitas Netral" | 4.38 | 10px / 600 | rgb(246,239,230) |

Source files: `src/app/components/DataFreshnessBadge.tsx`, `AccumulationBadge.tsx`, `AIAdvisorView.tsx`, `AllocationPanel.tsx`, `AlertsView.tsx`. The existing `contrast.test.ts` samples `#f5f7fa`/`#ffffff` only, so these warm tints sit outside the guard.

### F-02 (P1, R-25 + R-34 dark) Chips and section labels paint `--primary` (a fill) as text

Dark `--primary` is `#33507a` (theme.css:87), a navy meant for fills. It is used as a text color on dark surfaces:

- Markets filter chip "Semua": 1.53:1, `color: var(--primary)` on `background: var(--accent)` `#143a2f` (theme.css:94). Source: `MarketsView.tsx` filter row, inline style `color: var(--primary)`.
- Same chip row, unselected chip: 2.20:1 on ground rgb(14,23,38), `background: color-mix(in srgb, var(--primary) 12%, transparent)`.
- Settings "Tampilan" section label: 2.20:1 on rgb(14,23,38). Source: `SettingsView.tsx`.

`contrast.test.ts:220` states the rule in words: "`--primary` is a fill; the places where a link sits on the page ground use `--link` instead." The chips violate that. Light mode does not fail here because light `--primary` (`#14243a`) is dark enough.

### F-03 (P2, R-25 dark) Loss token as small text on dark chips falls just under the bar

`--loss` dark `#e26a6a` (theme.css:114) on rgb(45,44,64):

- SignalCard "Probabilitas Rendah": 4.20:1, 10px / 600.
- Alerts "TINGGI": 4.20:1, 8.5px / 700.

### F-04 (P1, R-26 + R-32) The position modal is a hand-rolled overlay: no dialog role, no Escape, no focus move

"Tambah Posisi Baru" (`PositionModal.tsx:116-158`) is plain DIVs. Verified live:

- `document.querySelector('[role="dialog"]')` is null while it is open.
- Pressing Escape with focus outside the modal (on the sidebar) leaves it open.
- Pressing Escape again with focus inside the symbol field leaves it open. No `onKeyDown` exists in the file.
- Opening the modal does not move focus into it (active element stayed on "Portofolio").

R-26 requires "A modal or dialog that opens and closes (closable with Escape)". R-32 requires "Dialogs and modals must be closable with Escape". This is the same component the `contrast.test.ts` guard names on line 68, so it is in scope by the project's own definition. Note the sibling `ConsentModal` (`ConsentGate.tsx:59-119`) does it correctly (`role="dialog"`, `aria-modal`, `aria-labelledby`), which makes the omission a deliberate divergence rather than a missing pattern.

### F-05 (P2, R-32) Icon-only buttons with no accessible name

Two `X` controls have empty text, no `aria-label`, and empty `title`:

- PositionModal close button (`PositionModal.tsx:152-157`).
- AIAdvisorView OJK banner revoke button (`AIAdvisorView.tsx:842-850`). This one silently calls `clearConsent(accountId)` and re-opens the consent gate. A screen-reader user gets an unlabeled button that revokes their compliance acceptance.
- Confirmed live: an empty-accessible-name button count of 1 on the Portfolio (with modal open) and on AI Advisor.

### F-06 (P1, R-26 + R-36) Consent is recorded on one view and not another, yet the modal copy promises server recording

`ConsentGate.tsx:40-48` writes the local marker and then POSTs `/v1/auth/consent`. `AIAdvisorView.tsx:797-800` renders the same `ConsentModal` with its own handler that only writes the local marker, so on the AI Advisor view the POST never fires.

Reproduced three times: after pressing "Saya Mengerti & Setuju" on the Advisor, the local key is written (`aidss.disclaimerAcceptedAt:<id>:v1`) but the network log shows zero `/v1/auth/consent` requests, `consent_acceptances` holds 0 rows, and `GET /v1/auth/consent` returns `accepted:false`. A direct `POST` from the same page returns 200 and stores a row, so the backend is fine; only the Advisor call site is missing the report.

The modal body tells the user the opposite: "Persetujuan dicatat di server dengan tanggal dan versi teksnya..." (`translations.ts:231`, English `:472`). The behavior does not back the claim. For a compliance gate this is the one direction that must not fail silently.

### F-07 (P2, R-32) Modal fields are not programmatically labeled

PositionModal inputs have no `id`/`name` and the `<label>` elements have no `htmlFor` (`PositionModal.tsx:191-266`). DevTools raised "A form field element should have an id or name attribute (count: 3)". Placeholder text is not a label substitute.

### F-08 (P3, R-03) Mobile tap targets under 44px

At 390px: hamburger "Buka menu navigasi" is 28x28, drawer close "Tutup menu" is 24x24, drawer nav items are 34px tall, "IDR/USD" is 34px tall. No horizontal overflow anywhere (document scrollWidth equals viewport on all views).

### F-09 (P3, note) Recharts container warning

Console logs `The width(64) and height(28) are both fixed numbers, maybe you don't need to use a ResponsiveContainer` about 30 times. Not a user-visible defect, but it indicates a fixed-size sparkline wrapped in `ResponsiveContainer`.

## Passes (recorded evidence, R-35)

- Theme toggle "Aktifkan tema gelap" flips `documentElement` to `.dark` and the localStorage key to `dark`; label becomes "Aktifkan tema terang". Both directions work.
- Language toggle flips `documentElement.lang` id to en; nav labels and the toggle label follow. Back again works.
- Search combobox ("Cari saham atau pasar"): typing "BB" opens a `listbox` with options BBCA and BBRI.
- Consent gate on the StockDetailPanel path (ConsentGate) closes on accept and does POST a row; this is the path that works.
- PositionModal validation shows text errors for unknown symbol, non-positive lots, and non-positive price (not color-only) and keeps the modal open.
- Empty/loading/error states present: News and Reports show empty states; view skeletons render on load.
- Console: zero errors across all nine views in both themes. Only the F-09 warning and F-07 a11y issue appear.

## What could not be verified

- Images: screenshots are saved to `.audit/` but unreadable by the reviewer, so visual-only defects (spacing, icon alignment) are out of scope for this pass.
- Admin "Blokir" was not fired (it would block the operator's own account). Its wiring was inspected only.
- TimescaleDB behavior (hypertables, continuous aggregates) is untested because the extension is absent in the throwaway cluster.
- The API responses come from a stale signal model, so the audit cannot confirm numbers are current, only that the UI renders whatever the API returns.

## Suggested order if fixes are approved

1. F-06 (compliance recording) and F-04 (modal Escape/role) are the two that break a stated contract.
2. F-01 and F-02 are the contrast batch, both fixable at the token or chip-style level.
3. F-05 and F-07 (accessible names, label association) are small, mechanical edits.
4. F-03, F-08, F-09 last.
